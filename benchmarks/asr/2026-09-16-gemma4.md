# Gemma 4 E2B: test before single-model integration

The native CPU experiment runs Gemma 4 E2B audio-to-text successfully, but does **not** justify replacing the two-stage default. A verified projector precision conversion reduced Gemma's direct-polish median from **5.22 s to 1.13 s** on the same 31 resident comparisons. Existing LFM → Qwen took **0.72 s** and roughly half the peak RSS. Direct and paired generation still produced content errors.

This adds a development benchmark, not a desktop Gemma adapter. Cohere → Qwen remains selected by default. [Issue #41](https://github.com/rahulsharmavishwakarma/transcribe/issues/41) contains scope, decisions and the integration boundary. The [complete evidence bundle](results/2026-09-16-gemma4.json) contains 21 reports and 555 request rows, including failures, exact prompts, references, hashes, timings, conversion provenance and four verified harness source snapshots. No audio is redistributed.

## Local comparison

Hardware: Apple M5 Pro, 18 logical CPUs, 64 GiB RAM, macOS 26.6.2; CPU execution with eight threads, AC power/default power mode. Data: 32 distinct English FLEURS test sentences, 294.1 seconds, 716 normalized reference words, approximately 4–20 seconds per recording. The source revision is `70bb2e84b976b7e960aa89f1c648e09c59f894dd`, licensed CC-BY-4.0; Google FLEURS/FLoRes attribution and individual audio hashes are retained in the bundle. No prompts were tuned on these results.

Latency excludes the first English sample ID in **every** path, giving the same 31 recordings; failed requests remain included. For the existing pipelines it is ASR + writing time. For the standalone example it includes audio decoding, frontend, fresh context, encode/prefill, generation and output validation. It excludes model verification/load, capture, UI, persistence and device-stop timing. Cohere reloads per job; its writing weights become resident. Therefore this is not a comparison against hypothetical resident Cohere. Gemma/LFM example weights remain resident, with fresh request contexts. Pipeline LFM retains its qualified 10-second segment planner; the isolated multimodal probes use complete clips without segmentation.

WER lowercases and normalizes punctuation/Unicode; it does **not** normalize equivalent numeric forms. For example, digits versus spoken number words can add edits without changing meaning. Do not rank Cohere's successful-only WER against 32-clip scores: two requests stopped at native duration-token limits. The other Cohere failures and the LFM pipeline failure were rejected rewrites with raw text preserved. Matching aggregate WER does not establish matching meaning or writing quality. Raw fallback also preserves ASR mistakes; it is not ground truth.

Peak RSS is measured by macOS `/usr/bin/time -l` across each process, including mapped model pages. The multimodal processes exercise all three modes. Memory footprint is separately retained in the bundle; it is not interchangeable with RSS. Background desktop activity was present. Benchmarks/builds were run sequentially by this task, but interference and thermal state were not continuously monitored. These are local screening results, not edge-device or SOTA claims.

## What the modes revealed

Gemma raw ASR scored 62/716 edits with BF16 and 60/716 with F16. Paired JSON completed its required format in 29/32 BF16 and 30/32 F16 cases; corresponding successful paired scores were 60/631 and 60/661. Those denominators differ because failures remain unscored, explicitly counted. LFM paired JSON succeeded in only 15/32 cases. No constrained JSON grammar was applied: these results measure the frozen prompt protocol, not the maximum schema reliability the runtime might support.

The F16 conversion changed six of 96 Gemma outputs; 90 matched exactly. Raw WER improved slightly, while polish WER worsened by one word edit. A meaningful example is the public genetic-variation sentence: the F16 polish changed *twentieth century* to *twenty-first century*. Another output changed a place name. The conversion cannot be described as quality-equivalent.

Six task-authored synthetic controls were spoken using macOS Samantha at 175 words/minute, mono PCM16/16 kHz. They are a separate control set, not conversational evidence. Both Gemma precisions changed *leave the draft unchanged* to *leave the draft on change* in polish and paired modes, while the independent raw ASR mode retained *unchanged*. LFM paired output changed the synthetic reference AB709 to AB7009 in both fields. Matching `raw` and `polished` therefore does not prove correctness. LFM direct polish also appended an unspoken explanation to a public sentence. On the spoken-instruction control, both existing two-stage paths rejected the attempted rewrite and retained raw text; Gemma's direct modes transcribed the instruction.

The four boundary cases comprise an 8.76-second source, three repetitions at 26.28 seconds, a shifted repetition at 28.28 seconds, and a different 10.56-second natural clip. Gemma raw/polish retained all repeated phrases, with recognition errors; paired format failed on the shifted repetition in both precisions. Unsegmented LFM raw omitted a repetition, reinforcing the separate [10-second production segmentation qualification](2026-09-15-lfm.md). This is not a natural long-conversation test.

An oversized 175.2-second synthetic input was rejected by the Gemma benchmark's 30-second contract. The next valid request exactly matched the preceding one. The four-clip, three-mode repeat tests matched all 12 outputs/errors within each fixed configuration. These are request-isolation checks, not cancellation-latency or live-streaming qualification.

A separate four-clip test used Google's temperature 1.0, top-p 0.95, top-k 64 preset with seed 123. All 12 responses met their output format, but names and factual wording still changed; one paired response again substituted the century. It is not pooled with greedy results and does not establish robustness across seeds.

## The measured CPU optimization

The original 12.64-second smoke request took 7.144 seconds: the native log attributed 6.076 seconds to audio encoding and 0.725 seconds to LM audio prefill; text generation took 0.232 seconds. With the selective F16 projector, audio encoding took 0.186 seconds and the request 1.248 seconds, with identical text for that clip. Across the comparable 31 direct-polish cases the reduction was approximately **4.6×**, with unchanged peak RSS. The safe helper reports encoding and LM prefill together; the individual smoke subdivisions above come from native logs.

The pinned [CPU matrix dispatch](https://github.com/ggml-org/llama.cpp/blob/e79e4bf660e19f2ad851e06c6913f7a8c5852621/ggml/src/ggml-cpu/llamafile/sgemm.cpp) and [BF16 dot implementation](https://github.com/ggml-org/llama.cpp/blob/e79e4bf660e19f2ad851e06c6913f7a8c5852621/ggml/src/ggml-cpu/vec.cpp) motivated this experiment: ARM F16 paths exist without equivalent BF16 paths. That is source evidence consistent with the measurement, not an instruction-level CPU profile. Build settings include `GGML_LLAMAFILE=ON`, `GGML_ACCELERATE=ON`, `GGML_BLAS=OFF`, `GGML_NATIVE=OFF`. No kernel or runtime was modified. The audio graph implements its own relative-position attention; a generic flash-attention setting is not an audio-encoder fusion switch here.

Increasing the physical microbatch from 128 to 512 on four clips/two repeats produced no useful gain. Second-repeat polish medians were 1.097 versus 1.083 seconds, paired medians 1.498 versus 1.548 seconds, and RSS increased by approximately 36 MiB. Two of 24 outputs differed between configurations. Retain 128 for the reported candidate; do not advertise this noisy microbatch result as an optimization.

The first process's artifact hashing alone took 7.27 seconds and loading 0.85 seconds. Startup verification and resident inference are separate costs; file caches were not flushed. Neither the FP16 speedup nor using one model eliminates that startup cost.

## Research and artifact boundary

**Paper result:** The [Gemma 4 report](https://arxiv.org/html/2607.02770v1) describes E2B's Conformer audio encoder, local/global attention and shared KV layers. Global key=value reuse explicitly excludes E2B/E4B. Its mobile quantization/memory results do not describe these CPU GGUF measurements.

**Official capability:** [Google](https://ai.google.dev/gemma/docs/core/model_card_4) specifies multimodal inputs and text output. E2B is approximately 2.3B effective / 5.1B total parameters, exceeding the earlier total-2B ceiling; this explicit requested test is an exception. An “any-to-any” tag does not establish speech generation. The [audio contract](https://ai.google.dev/gemma/docs/capabilities/audio) specifies mono 16 kHz float32 in [-1,1], up to 30 seconds. Source template/config pin: `google/gemma-4-E2B-it@3e22461f65e89153144f8adb70e3b8c2cc9845a7`.

**Local measurement:** Everything in the tables/control results above uses pinned native code and the specified artifacts. No model is added to the production registry or installer.

**Unverified hypothesis:** Broader conversational quality, personal vocabulary, other languages, automatic language detection, singing, code-switching, live streaming and smaller edge-device performance may differ. [Ultravox 0.5/Llama-3.2-1B](https://huggingface.co/fixie-ai/ultravox-v0_5-llama-3_2-1b) is a further speech/text-to-text candidate around 1.92B total including its audio component; it was researched, not executed or qualified. Its adapter's MIT label does not replace the bundled Llama terms.

The implemented experiment is **frozen-weight public-API work**: native media processing, fresh contexts, measured batching and a separately verified artifact conversion. New fused audio attention or ARM BF16 kernels would be **runtime-internal work**. QAT/distillation/retraining are **training/checkpoint changes**; using Google's published QAT backbone does not implement those methods locally. The [paper-to-engineering map](../../docs/research-streaming-inference-papers.md) keeps these categories separate.

## Reproduction

Use `llama-cpp-2 = 0.1.156`, whose bundled llama.cpp revision is `e79e4bf660e19f2ad851e06c6913f7a8c5852621`. The benchmark uses context4096, batch512, physical microbatch128, output limit1024, eight CPU threads, no thinking, and greedy sampling unless explicitly selected otherwise. The backbone has zero GPU layers and an empty device list; projector/context offload is disabled. Unexpected modality/control tokens, empty/malformed output, nonfinite logits and missing valid termination are failures. The 120-second deadline is cooperative between native calls/tokens, not an immediate encoder abort.

Google artifact repository: [`google/gemma-4-E2B-it-qat-q4_0-gguf`](https://huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf/tree/675cff42a74c774d6cb76f76d8eacb49b48c9b93), revision `675cff42a74c774d6cb76f76d8eacb49b48c9b93`, Apache 2.0:

The initial plain F16 conversion **aborted** on a four-dimensional convolution tensor. Its partial output was never loaded. The verified conversion preserved all 1,164 original F32 payloads byte-for-byte and changed only the 247 BF16 matrices to F16; all 1,411 names/shapes match, and there are no Q8/BF16 output tensors. Native finite-row validation passed. Full caller source, binary/library hashes, parameters and failure provenance are in the bundle.

The following is the source-verified upstream CLI equivalent. Local conversion executed the recorded temporary C++ caller linked to the existing native archives, **not this CLI**. Preserve flag order and use a fresh output path. In this revision F16 dispatch ignores tensor overrides, so Q8 dispatch activates the explicit F32/F16 overrides; the final artifact contains no Q8 tensors and is labelled F16 through the metadata override. See the [pinned converter](https://github.com/ggml-org/llama.cpp/blob/e79e4bf660e19f2ad851e06c6913f7a8c5852621/src/llama-quant.cpp).

```sh
llama-quantize \
  --tensor-type '^a\.blk\.[0-9]+\.conv_dw\.weight$=f32' \
  --tensor-type '^a\.input_projection\.weight$=f32' \
  --tensor-type '^a\.conv1d\.[01]\.weight$=f32' \
  --tensor-type '^v\.(patch_embd|position_embd)\.weight$=f32' \
  --tensor-type '^.*$=f16' \
  --override-kv 'general.file_type=int:1' \
  INPUT-mmproj.gguf OUTPUT-mmproj-f16.gguf Q8_0 8
```

Prepare the pinned FLEURS data using the [benchmark guide](README.md), then select the exact 32 IDs/references/hashes in `manifests.english32` of the bundle. Extract the other manifests for their separate suites. Populate the environment with the actual hardware, power, backend and source revision; do not reuse this machine's label for another device.

```sh
. ./scripts/dev-env.sh
cargo build --release --locked -p transcribe-eval \
  --example multimodal --bin transcribe-eval

target/release/examples/multimodal gemma4-f16 MODEL_DIR \
  MANIFEST CORPUS_ROOT ENVIRONMENT OUTPUT_JSON raw,polish,paired 1 greedy 128

target/release/transcribe-eval run MANIFEST CORPUS_ROOT models/downloads \
  ENVIRONMENT OUTPUT_JSON --model LiquidAI/LFM2.5-Audio-1.5B \
  --language en --cleanup
```

Use `gemma4` for the original projector and `lfm2` for the isolated LFM probe. Use `CohereLabs/cohere-transcribe-03-2026` for the default pipeline baseline. Both artifact hashes are checked before native loading. Repeat/sampling variants and all exact prompts are recorded in the bundle.

Verification: all **18 evaluation tests**, strict Clippy for every evaluation target, formatting, and release compilation passed. The source snapshots distinguish harness revisions during unrelated desktop edits; native inference sources and runtime pins remained fixed. No files were staged or committed by this work.
