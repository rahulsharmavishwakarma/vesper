# ADR-0012: Register inference contracts and apply reviewed local preferences

Status: Accepted

Date: 2026-09-15

Approval and scope: [#35](https://github.com/rahulsharmavishwakarma/transcribe/issues/35#issuecomment-5684028145), [#34](https://github.com/rahulsharmavishwakarma/transcribe/issues/34#issuecomment-5684029968). Performance qualification and deferred work remain in those issues.

## Context

Checkpoint-specific dispatch repeated capability assumptions. Qwen evaluated invariant instructions on each of two dependent cleanup passes. Reviewed transcripts existed, but no explicit local preferences consumed them. The product needs extensible native inference with measurable CPU/edge cost.

## Decision

`vesper-core::ADAPTERS` registers compiled task/architecture/runtime contracts. Built-in identity resolves to a registration; imported checkpoints still require validated, pinned artifact layouts. New compatible sherpa-transducer or llama.cpp GGUF profiles remain declarative. New native architectures require compiled adapter code. Remote repositories cannot execute code.

Speech and text dispatch use separate adapter enums at request boundaries. Native NeMo, sherpa, Candle and llama.cpp retain ownership of kernels, frontend/tokenizer behavior, decoding, and state. Existing NeMo/Qwen weights remain resident; other adapters retain their truthful per-job/process lifetimes. No lookup or generic tensor layer enters a native frame/token loop. Registrations distinguish actual application streaming from a checkpoint's theoretical streaming capability.

The pinned Nemotron adapter passes the C ABI's `rnnt_right_context=-1` at recognizer creation, selecting the artifact's own default. The checkpoint declares default right context 3 and supported values `[3, 0, 6, 13]`; a null streaming configuration instead inherited the native runtime's right context 1. The wrapper initializes every field of the versioned streaming structure, including valid CTC geometry, because the runtime copies and validates those fields even for RNNT. This is specific to the qualified checkpoint. The live CPU log confirms left 56/right 3 and a nominal encoder advance of 320 ms; that advance is neither measured first-partial latency nor Stop-to-final latency.

The existing SQLite store holds a bounded local profile with monotonically increasing revisions and optimistic concurrency checks. Vocabulary and presentation preferences require explicit save. Remembering a cleanup example is a separate action after a human review; the database validates its original input, reviewed target, language, preset and review ID. Removing or pausing entries prevents future retrieval after save. A newly remembered review replaces that session's prior example. Saving an ordinary label never activates a preference.

Each operation freezes one profile snapshot. Language-filtered, untagged vocabulary can be sent to native NeMo requests, with opt-in uniform boost 2, at most 32 phrases, 128 bytes per phrase and 2048 bytes total. Context-tagged spellings are restricted to text cleanup, because no reliable lexical context exists before ASR. Automatic-language requests use only entries explicitly marked any/automatic. Unsupported speech adapters receive no bias and report the capability explicitly.

Cleanup uses deterministic lexical set similarity, not an embedding model or learned intent classifier. At most two relevant examples are selected by language, preset and explicitly selected output form; shared stopwords alone cannot trigger retrieval. JSON quotes reference data, input control-token checks remain active, and the original raw text remains the fidelity baseline. Optional context is limited to 512 tokenizer tokens and dropped on prompt pressure. Technical-tail and full-cleanup passes remain sequential; a reference-assisted first pass still uses the existing narrow correction guard. Selected output forms only guide punctuation/presentation, never action execution.

The optional prefix experiment uses safe `state_seq_get`/`state_seq_set` with empty flags and fresh contexts. That includes attention and recurrent state. Cached host snapshots stop before the user message and are checked against the complete prompt's actual token IDs. A snapshot belongs to its loaded artifact/runtime/backend, exact prefix, profile revision and context geometry. Personalized reference prompts and arbitrary custom GGUF templates are excluded. At most two snapshots share a 64 MiB payload budget, with eviction before replacement allocation. Restore failure discards the changed context and invalidates the entry. No transcript tokens are retained. Enable only explicitly with `TRANSCRIBE_EXPERIMENTAL_PREFIX_CACHE=1`; local screening does not qualify every device or language.

Per-pass metrics report tokenization, context creation, restore, synchronization plus snapshot, synchronized prefill, first token, generation, total time, token counts, decisions and retained cache bytes. Recording provenance and diagnostics contain profile IDs/revisions and execution evidence, never prompt/example contents. Static requested/selected backend is separated from successful initialization and operator placement. Placement remains unknown where the pinned API provides no accessor. Explicit-backend policy is part of resident keys, preventing reuse of an Auto CPU fallback for a later explicit GPU request.

## Evidence and boundaries

| Class | Evidence | Application consequence |
| --- | --- | --- |
| Primary research | [Prompt Cache, MLSys 2024](https://arxiv.org/abs/2311.04934) studies reuse of repeated prompt computation. | Informs exact contiguous prefix reuse; this is not a reimplementation of the paper's modular attention system and inherits none of its speedup claims. |
| Primary research | [Stateful Conformer with Cache-based Inference](https://arxiv.org/abs/2312.17279) couples constrained contexts and activation reuse with compatible training. | Use the checkpoint's supported contexts; changing lookahead arbitrarily is not an accuracy-preserving switch. | Primary research | [LaMP](https://arxiv.org/abs/2304.11406) evaluates retrieval from personal profiles. | Motivates bounded retrieval; lexical ranking/budgets here are engineering hypotheses, not results established by LaMP for dictation. |
| Primary research | [Zhao et al., Interspeech 2019](https://www.isca-archive.org/interspeech_2019/zhao19d_interspeech.html) studies contextual ASR biasing. | Requires positive and anti-context evaluation. Its beam/training techniques are not switches in the downloaded Nemotron artifact. |
| Official capability | [Transformers AutoClasses](https://huggingface.co/docs/transformers/en/custom_models) separate configuration/model identity from implementation. | Adopt the separation while preserving compiled native adapters and declarative downloads. |

These are frozen-weight application/runtime changes (category 1). New attention/decoder kernels, cache precision and fusion changes require runtime-internal work (category 2) and are not implemented here. LoRA, distillation, ASR adaptation and learned intent classifiers require training/checkpoint work (category 3), separate supervised datasets, conversion checks, held-out gates and promotion/rollback under #5. No live self-training or automatic promotion is introduced.
