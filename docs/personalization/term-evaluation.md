# Term evaluation: recognizer hooks and the correction gate

This fixed evaluator decides, per speech model, whether per-recording vocabulary helps or harms. It qualifies the [typed recognizer hooks](context-selection.md#typed-recognizer-hooks) and measures the text-level [correction gate](correction-gate.md) on every model. The learner cannot read or change it.

## Protocol

- **Corpus.** Generated by [`benchmarks/asr/python/term-eval`](../../benchmarks/asr/python/term-eval/README.md) and frozen by hash in [`benchmarks/asr/manifests/term-eval/FROZEN.json`](../../benchmarks/asr/manifests/term-eval/FROZEN.json) before any model output was produced. Three synthetic workspaces of 30 terms; positives are synthetic TTS (macOS `say`, several English voices); target-free hard negatives are text, with a rendered subset; cached FLEURS en-US clips are real-speech target-free controls. Generated audio stays in the ignored benchmark cache.
- **Conditions** (the working set for each sample):
  - `none`: no hints.
  - `ws10`, `ws32`: the sample's workspace, with its target terms first, at 10 and 32 hints.
  - `wrong32`: all terms of a different workspace (targets absent).
  - `large`: every workspace term plus distractors (150 entries), with the hook's limits lifted by the evaluator; native runtime limits still apply.
- **Arms.** All arms are recomputed from saved raw outputs by `term-score`, without re-decoding. Hook-less models decode once; their gate arms apply each condition's working set to that decode.
  - `raw`: the recognizer output.
  - `gate_exact`: `correction_gate_with(raw, &set, English, NearMiss::Off)`. Normalizations come from each hint term's spoken forms (identifier splits), as user-asserted spellings.
  - `gate_exact_authored`: the same, as project-authored spellings, which may not rejoin ordinary words.
  - `gate_near_miss`: exact plus `NearMiss::Apply`, with up to 16 of the condition's spellings as `references`. Near-miss changes are counted separately.
  - `cleaned`, `cleaned_gate_exact`: the optional writer arm (`--cleanup`) on a subset, with the condition's terms as profile vocabulary.
- **Metrics.**
  - Target-term recall, exact spelling, case-sensitive and case-insensitive.
  - Non-target WER (U-WER, after Le et al. 2021): errors on reference words outside target-term spans; insertions of hint words count against targets.
  - False alarms per target-free utterance: any hint term absent from the reference appearing in the output, or any gate change. Reported with a 95% one-sided Clopper–Pearson upper bound.
  - Harmful gate edits per 1,000 reference words (a change whose spelling is absent from the reference, or whose heard span was in it), with near-miss changes and near-miss false alarms reported separately.
  - Hint-induced regressions: utterances whose WER rises with hints compared with the paired `none` decode.
  - Added latency p50/p95 against the paired `none` decode, and gate time.
  - Failed decodes stay in every denominator: a failed positive counts as a miss.

## Running it

```sh
. ./scripts/dev-env.sh
cargo build --release --locked -p vesper-eval
target/release/vesper-eval term-decode TERM_MANIFEST CORPUS_ROOT MODEL_ROOT ENVIRONMENT OUT.jsonl \
  --model Qwen/Qwen3-ASR-0.6B [--conditions none,ws10,ws32,wrong32,large] [--denoiser dpdfnet8] [--cleanup]
target/release/vesper-eval term-score TERM_MANIFEST SCORES.json OUT.jsonl [MORE.jsonl ...]
```

`term-decode` appends one JSON row per sample and condition, resumes an interrupted run, verifies audio hashes and writes `OUT.meta.json` with the environment, hook descriptor, model versions and artifact provenance. It sends hints to unqualified (`declared` or `disabled`) hooks (evaluator only), lifts hook limits only for `large`, records the audio frontend's execution evidence and turns a requested frontend that did not run into a failed row. A model root must hold the frontend artifacts as real files, not symbolic links. `term-score` adds text-only samples as the `reference-text` lane, where the hypothesis is the reference itself.

- **Text-only negatives:** 0 gate changes and 0 near-miss changes on 2,595 sentences in every condition (≤0.12% at 95%).
- **Authored tier** (`gate_exact_authored`, which may not rejoin ordinary words) recovers almost nothing on these positives (Cohere 33.9%, Parakeet 29.2% exact at ws32, 2–3 changes), because most spoken forms here are ordinary-word splits; on LibriSpeech it keeps most of the gain (84.6% and 79.2%).

On Cohere and Parakeet output, near-miss repairs never touched a synthetic negative.

## Hook decisions

Gates are the predeclared ones in [native qualification](native-qualification.md#recognizer-hook-qualification).

| Hook | Benefit | ≤1 pt FA increase, upper bound ≤3% | FLEURS WER ≤ +0.5 pt | No new failures | Status |
| --- | --- | --- | --- | --- | --- |
| Nemotron `phrase_bias` | pass (+39.9 / +38.7 pts) | **fail** (ws32 +21.1 pts hard negatives, +33.7 pts FLEURS) | **fail** (+6.9 pts) | pass at ws10/ws32 | **`disabled`** |
| Qwen3-ASR `prompt_context` | pass (+38.6 / +40.4 pts) | **fail** at ws32 (+2.3 pts, upper bound 4.1%); wrong32 passes on hard negatives | pass (+0.3 pts) | pass at ws10/ws32 | **`disabled`** |

The upper bound in the false-alarm gate cannot be met on the FLEURS lane by any configuration: 92 clips with zero events still give a 3.2% bound. Read per lane, that gate fails every hook on FLEURS; the decisions above rest on failures that do not depend on that reading. See [round 2](#round-2-ordinary-word-filter-and-lower-nemotron-boosts) for both readings.

Both hooks raise term recall substantially, which is consistent with the published picture that biasing raises recall while precision falls. Neither passes the false-alarm gate, so neither receives automatic hints. Vocabulary reaches every model through the correction gate, which added 10–12 points of exact recall on Cohere and Parakeet with no measured harm on target-free speech in its exact mode. The Settings opt-in phrase list still reaches Nemotron, as before; the Nemotron result suggests reviewing that switch.

## Round 2: ordinary-word filter and lower Nemotron boosts

Same frozen corpus (with the supplement), same predeclared gates and thresholds, conditions `none`, `ws10`, `ws32` and `wrong32` on clean positives (n=158), rendered hard negatives (n=350) and FLEURS (n=92). Two principled changes, both in the application code (`c1252b6`):

- **Ordinary-word filter.** Automatic hints drop every surface whose words are all in the gate's ordinary-English lexicon (`ordinary_language`). From the 90 synthetic terms this removes 24: Helm, Prometheus, kube-proxy, Envoy, Calico, Jaeger, Thanos; tokio, Svelte, NeMo, cargo-deny, Parakeet; Vesper, Nguyen, Wright, Mandy, Cedar Point, Joaquin Phelan, Paige, Bree, Niall, Sloane Ferreira, Tadeusz Kowalczyk, Dashiell. The lexicon includes CMUdict's names, so several real names are dropped too; their targets still count in recall. The gate keeps all of them.
- **Lower uniform Nemotron boosts** (1.0 and 0.5, plus 2.0 with the filter), through the evaluator's `--boost`.

Decoded with evaluator `c1252b6` (`3e4f1d16…`). That revision sent boost 0 with an empty list, which the NeMo FFI rejects, so all 600 Nemotron `none` rows failed; the fix (`8efb24b`, an application bug that would have broken every unbiased Nemotron decode) restored 2.0 for unbiased decodes, and those rows were re-decoded with `8efb24b` (`vesper-eval-v4`). The failed rows are kept locally.

- **Qwen3-ASR stays `disabled`.** The filter removed most ordinary-word false alarms (8 → 1 hard negatives at ws32) at the cost of about 11 recall points, but the prompt still changes decoding outside the terms: on FLEURS it emitted the whole hint list as text (in place of "radio site TogiNet Radio" at ws32, and inside another clip at wrong32), and it dropped spans of ordinary speech ("along with an extra set in the roof of its mouth"). FLEURS WER rose by 1.6 points. This failure does not depend on how the bound is read.
- **Nemotron 0.5 with the filter** adds 7.1 points of exact recall with no measurable change on FLEURS and one extra hard-negative false alarm. It passes every gate except the FLEURS upper bound read per lane, which no configuration can pass with 92 clips. Under the predeclared text it is **not qualified**, and the hook stays `disabled` at its configured boost 2.0. Qualifying it needs either an owner decision that the bound applies to the pooled target-free set (4/442, ≤2.1%), or at least 99 more fresh real-speech negatives added as a new predeclared lane. Its recall gain is also modest: on the same positives, the exact correction gate alone added 9.6–11.9 points on Cohere and Parakeet.
- **Recall against false alarms for Nemotron (ws32, filtered):** boost 0.5 gives 20.8% recall with 1.1% / 0.0% false alarms (hard negatives / FLEURS); 1.0 gives 32.1% with 2.0% / 3.3%; 2.0 gives 43.5% with 16.3% / 33.7%. The filter alone at 2.0 lowered hard-negative false alarms from 22.0% to 16.3% and left FLEURS unchanged.
- **Correction gate on these decodes** (current gate): on Nemotron 0.5 ws32 the exact gate raised exact recall from 20.8% to 32.1% (19 changes, 0 harmful) with no added false alarms; near-miss raised it to 39.9% (13 near-miss changes, 0 harmful on positives) but made 4 harmful near-miss repairs on biased hard negatives ("bright room" → "Brightloom"). On filtered Qwen3-ASR ws32 the exact gate reached 53.6% exact recall and made one harmful change on a hard negative. Near-miss repairs on biased decodes compound the bias; the shadow default stays the safer reading.

Remaining candidates, as hypotheses only: a guard that rejects a transcript echoing the hint list (Qwen3-ASR); a larger real-speech negative lane so the bound can be met.

## Limitations

- Positives and most negatives are synthetic TTS of templated sentences; real dictation, accents and microphones are not covered. Real speech enters only through 92 FLEURS clips and 271 LibriSpeech utterances.
- The ordinary-word supplement (72 clips) was added after the corpus freeze but before any model output was produced; the frozen negatives alone would have shown Qwen3-ASR at 1/278.
- Upper bounds on FLEURS are wide (n = 92 gives ≤3.2% even with zero events).
- Nemotron was measured on completed audio, not the live stream the app uses for drafts.
- The writer arm uses `none` and `ws32` only, on a 180-utterance subset; it uses profile vocabulary, not working-set references.
- Latency was measured on a shared machine on battery power.
- Two scorer defects were fixed after the first runs were scored (case-insensitive harm, and a DPDFNet8 run whose model root lacked frontend artifacts so the manager silently used original audio). No condition, threshold or list was changed; the invalid run is kept locally and excluded.
