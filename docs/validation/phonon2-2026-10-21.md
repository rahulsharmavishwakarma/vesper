# Phonon-2 adapter — 21 October 2026

Question ([#231](https://github.com/rahulsharmavishwakarma/vesper/issues/231)):
can Fermion Research's Phonon-2 run in Vesper through an adapter built around
its packed format? If so, what does its small size cost in accuracy compared
with Parakeet v3?

**Result: added as an optional small English model for Apple Silicon.** It is
never a default.

Phonon-2 needs about a seventh of Parakeet v3's MLX download and under a quarter
of its GPU memory. In exchange it is somewhat less accurate: significantly so
on unseen FLEURS clips and quiet speech. It is not faster. Use it when disk
space or memory matters more than the last points of accuracy. Otherwise prefer
Parakeet v3 or Granite.

| Lane (Metal, app path) | Parakeet v3 | Phonon-2 | Phonon-2 − v3 (95% CI) |
| --- | --- | --- | --- |
| FLEURS en-US held-out, 94 clips | 5.25% | 5.75% | [−0.35, +1.32] |
| FLEURS en-US unseen, 100 clips | 5.68% | 7.43% | [+0.68, +3.06] |
| Natural clean, 24 | 6.25% | 7.73% | [−0.33, +3.48] |
| Natural +10 dB SNR, 24 | 6.74% | 7.57% | [−0.77, +2.74] |
| Natural 0 dB SNR, 24 | 9.21% | 10.86% | [−1.18, +4.35] |
| Quiet (−30 dB), 24 | 6.91% | 8.88% | [+0.19, +3.85] |
| Joined FLEURS long-form, 6 × ~95 s | 10.50% | 9.38% | [−4.88, +1.54] |

| Resource (FLEURS en-US, Metal) | Parakeet v3 MLX | Phonon-2 |
| --- | --- | --- |
| Median / p95 ASR time per clip | 48 / 71 ms | 55 / 86 ms |
| Peak MLX allocator memory | 3.80 GB | 0.86 GB |
| Model load | 218 ms | 167 ms |
| Download | ~2.5 GB | ~351 MB |

For comparison, Moonshine Base (CPU, ~141 MB) scores 10.11% on the held-out
set. Granite Speech 5.0 TurboCTC (Apple GPU, ~948 MB) scores 5.30%.

These are local measurements on read English speech, from one M5 Pro on battery.
Fermion's card claims a 5.21% Open ASR English average. That is a publisher
figure that this record neither reproduces nor contradicts. A public
leaderboard listed 7.23%.

## Model and evidence classes

- **Model:** [FermionResearch/Phonon-2](https://huggingface.co/FermionResearch/Phonon-2).
  - A compressed NVIDIA Parakeet TDT 0.6B v3.
  - English only. The weights are CC-BY-4.0.
  - Each encoder projection holds five weight values per row.
- **MLX build:** [mlx-community/Phonon-2](https://huggingface.co/mlx-community/Phonon-2/tree/1f228c19b37231d6ef8d839f8648bd4172bb097c)
  at `1f228c19b37231d6ef8d839f8648bd4172bb097c`.
  - It repacks Fermion's codes into two MLX 2-bit planes, retains the fp16 row
    palettes, and stores the dense tables in bf16.
  - Vesper installs it unmodified.
- **Reference implementation:**
  - mlx-audio 0.6.1, `stt/models/phonon2`.
  - The packed layer is adapted from fermion-research 0.2.11 (Apache-2.0).
  - Fermion's own Apple runtime (fermion-research 0.2.12) decodes through the
    same mlx-audio graph and returns its text unchanged.

## Adapter design

1. **Packed layers** (`native/mlx/Sources/VesperMLX/Phonon2.swift`).
   - Each of the 264 encoder projections stores two 2-bit code planes q and s
     plus per-row fp16 palettes lo and hi:
     `w = lo·(q − 1) + (hi − lo)·(s − 1)`.
   - This runs as two native MLX affine 2-bit matmuls (group 128):
     - scale `lo`, bias `−lo`;
     - scale `hi − lo`, bias `−(hi − lo)`.
   - The scales are derived once in float32. They are not module parameters,
     so the loader's later bf16 cast cannot round the palettes.
   - Kernel-1 pointwise convolutions use the same projection.
2. **Upstream graph.**
   - Everything else is the pinned MLX-Audio-Swift Parakeet TDT model:
     frontend, subsampling, attention, decoder, joint and greedy TDT.
   - A small pinned patch (`patches/mlx-audio-swift/parakeet-load-hook.patch`)
     lets VesperMLX swap the encoder modules before strict weight
     verification. Stock Parakeet loading is unchanged.
3. **Digit-spacing repair** (a Vesper adaptation).
   - The compressed encoder often emits digit pieces without the word-boundary
     marker: "about70 km", "in1990", "around800 .". The reference runtimes
     return that text unchanged.
   - The adapter restores those boundaries: a space between a word and the
     following number, no space before closing punctuation, and joined numeric
     ranges.
   - It leaves acronyms with digits ("MP3", "H2O"), ordinals ("4th") and
     plurals ("1990s") alone.
4. **Parts of at most 30 s**, as for Parakeet v3 on Metal.
5. **Apple GPU only.**
   - Automatic and Metal run the model; CPU and other GPUs are refused.
   - A GPU initialization failure reports that the model has no CPU version.
   - Fermion's CPU engine uses its own container format and is not integrated.

## Digit-spacing repair evidence

The rules were written after reading held-out failures. They were then checked
on 100 FLEURS en-US test clips that share no sentence with the held-out sets.
These figures come from the reference implementation on identical float input:

| Set | Raw | Repaired | Parakeet v3 | Clips made worse |
| --- | --- | --- | --- | --- |
| FLEURS held-out, 94 | 7.15% | 5.55% | 5.25% | 0 |
| FLEURS unseen, 100 | 9.00% | 7.43% | 5.73% | 0 |

Before the repair, 32 of Phonon-2's 38 extra errors relative to Parakeet on the
held-out set were in sentences containing numbers. The repair recovers most of that gap but not
all of it. Phonon-2 also misreads some words and names that Parakeet gets right.

## Parity with the reference

- **Packing:** random five-value codes packed into MLX 2-bit planes give the
  dense-formula result (`testPackedPlanesEqualTheDenseFiveValueWeights`).
- **Whole model:** on three clips (synthetic speech plus two FLEURS clips), the
  Swift model produces the same text as mlx-audio's Phonon-2.
- **Repair rules:** the Swift repair matches the Python rules used for
  qualification on all 290 real hypotheses, 43 of which change.

`native/mlx/Tests/VesperMLXTests/Phonon2Tests.swift` holds these checks. The
fixture-based ones run when `VESPER_PHONON2_PARITY` or
`VESPER_PHONON2_REPAIR_PAIRS` is set.

## Environment

- Application branch `feature/phonon2-mlx-adapter` (commits in #231).
- MLX-Audio-Swift `d302a5c` with Vesper's three patches.
- Apple M5 Pro, 18 logical CPUs, 64 GiB; macOS 27.0.1; on battery.

The evaluator is `vesper-eval run … --model FermionResearch/Phonon-2 --language en`
with a Metal environment file and no audio frontend.

The unseen set takes the next 100 qualifying unique sentences of the pinned
FLEURS en-US test split (4–20 s, as `scripts/prepare-fleurs-benchmark.mjs`
selects), excluding every held-out sentence. The noise and long-form lanes are
the ones used for [Granite](granite-speech5-turboctc-2026-10-21.md).

## Limitations and deferred work

- **English only;** no automatic language detection.
- **No CPU path.** Fermion's CPU engine and Core ML build would each need a new
  runtime.
- **Speed.** Fermion's optional `dense16` mode would trade memory for speed by
  densifying the encoder. It is not used: it would remove the memory advantage.
- **Single machine.** Older or lower-memory Apple Silicon remains to be measured
  (#137).
